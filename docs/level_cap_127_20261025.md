# Intégration du plafond de niveau 127 — 25 octobre 2026

La progression normale du personnage et des compagnons passe de 50 à **127** dans le moteur, sur les builds x64 et x86. L’ancien programme `arcanum50patch.exe` n’a pas été exécuté : ses modifications binaires ciblent le moteur d’origine.

## Courbe d’expérience

Les seuils 1 à 100 viennent du `xp_level.mes` présent dans le dossier fourni, attribué à Alqualos. Les seuils 1 à 50 restent ceux de cette table originale ; après 100, l’intervalle augmente de 1 000 XP par niveau, dans la continuité de la fin du fichier.

| Niveau | XP minimum |
| --- | ---: |
| 50 | 1 300 000 |
| 51 | 1 353 000 |
| 100 | 5 201 000 |
| 127 | **8 360 000** |
| 128, seuil interne uniquement | 8 491 000 |

La documentation du patch précise le décalage d’un niveau propre à la version 1.0.7.4. Le moteur conserve ce mécanisme avec une borne interne à 128, afin que **127 soit réellement atteignable**, sans accorder de niveau 128. Il conserve aussi le rattrapage des compagnons au plafond. Le réglage explicite par `level_set` est borné à 127.

Le fichier livré est `resources/rules/xp_level.mes`. Les valeurs peuvent être personnalisées dans le jeu via `data/rules/xp_level.mes`. Le moteur valide les seuils : entiers positifs, croissance stricte et plafond numérique compatible avec les statistiques d’expérience. Si seule l’ancienne table est disponible, il ignore sa dernière sentinelle et génère la prolongation ; les entrées haut niveau absentes ne deviennent plus des seuils à zéro. Une table personnalisée étendue reste prise en compte.

## Points et corrections associées

La règle de gain reste un point par niveau, avec un point supplémentaire tous les cinq niveaux. De 1 à 127, cela représente **151 points gagnés**, auxquels s’ajoutent les cinq points initiaux. Le plafond des points non dépensés est donc relevé à **156**, pour ne pas tronquer les gains lors d’une montée de plusieurs niveaux.

Le calcul du pourcentage d’expérience utilise un intermédiaire entier 64 bits, reste borné entre 0 et 100 %, et affiche une progression nulle au niveau maximal. Les champs de texte existants accueillent les niveaux à trois chiffres.

Le test dans le moteur a révélé une récursion de l’ancien chemin de plafonnement : modifier l’XP via le setter de statistique rappelait le calcul des niveaux, qui rappelait le même setter. L’écriture interne du seuil d’arrêt évite maintenant ce rappel et conserve le traitement des compagnons.
